# The archive page: every game before the record

**Grammar:** claims-v1

**Claim:** I open poker.kmikeym.com/archive/ and see every game before July 2026, season by season, with who finished on the podium, which bounties were recorded, and how many played, and the standings page links me there instead of promising a backfill. (elicited)

**Goal:** Add `/archive/`, a generated page presenting the 2020 season, the 2025 season, and the 2026 games before the cards, from a new file `site/data/archive.json` that nothing else on the site reads. Retire the `backfillPending` list and the "being backfilled" sentence in favour of a link to the archive. Generated by `tools/render.ts`, committed as HTML, drift-checked as the sixth generated path. No runtime, no new service.

**Tech Stack:** Bun + TypeScript (`bun test tools`), static committed HTML under `site/` on Cloudflare Pages with `pages_build_output_dir = "site"` and no build step.

**Spec:** `docs/superpowers/specs/2026-09-05-archive-page-design.md` (reference for the reader; every fact a task needs is restated in its own Context)

## Global Constraints

- **No invented players and no invented numbers.** Every name, date, place, entrant count, and bounty in `site/data/archive.json` comes from a source a task's Context names, transcribed as it stands there. A value the source does not state is absent, never guessed, never zero standing in for unknown. The page prints "Entrants not recorded" for an absent count and nothing at all for an absent bounty list.
- **Names.** First name plus last initial, matching `/^[A-Z][a-z]+( [A-Z]\.)?$/`, the same expression `tools/data.test.ts` applies to `games.json`. Two exceptions, both already allowed by `docs/brand.md`: a first name alone with no initial, and a handle used as the name when the entry's `handle` equals its `name`. A player on the spine uses the exact `name` their entry in `games.json` `players` carries.
- **Slugs.** An archive entry may carry a `slug` only if that slug has at least one result in `games.json`; the page links a slugged name to `/player/<slug>/` and prints an unslugged name as text.
- **The archive feeds nothing.** No trophy, no standings row, no player page reads `archive.json`; `tools/lib/trophies.ts` and `tools/lib/standings.ts` do not import it.
- **Copy rules.** No em dash anywhere in `site/` output or in `archive.json`; the word "experiment" never; no `btn-primary` on the archive page; no new nav item (the nav stays Home, Games, Cards, Standings).
- **Visual system.** Light page, dark objects; `band-light` and `band-dark` alternate with no two adjacent bands of one tone, including the footer; the games index's own classes (`season`, `season-card`, `eyebrow`, `season-date`, `podium`, `stat`) with no new stylesheet rules; the foil gem on first place.
- **Deterministic render.** Nothing reads the clock; `bun tools/render.ts` twice produces byte-identical output.
- **Canonical data.** `site/data/archive.json` and `site/data/games.json` stay in `JSON.stringify(data, null, 2)` form with a trailing newline.
- **Generated pages are never hand-edited.** `site/archive/index.html`, `site/standings/index.html`, and `site/games/index.html` are written only by `tools/render.ts`; the drift check in `tools/site.test.ts` stays green on the integrated tree.
- **One list.** The README's 2020 table is replaced by a link to the archive page; no season's games are listed in two places.
- **Test fixtures are synthetic** (invented names and slugs) except the tests that read the committed data files.

**Parallelization rationale:** Wave 1 is two independent tasks: Task 1 (the archive data module) and Task 3 (retiring the backfill). Wave 2 is two: Task 2 (the renderer) imports Task 1's types and bounty table, which do not exist at BASE, and asserts markup built from that table, which is runtime behaviour; Task 4 (the first data file) runs Task 1's validator against the committed file, which is that validator's runtime behaviour, not its shape. Tasks 2 and 3 both modify `tools/render.ts` and `tools/render.test.ts` in different regions; those are text edits and fold. Wave 3 is one: Task 5 executes the renderer to produce the committed HTML, which needs the bytes Tasks 2 and 3 emit, and reads the data Task 4 wrote.

**Acceptance:** suite — `bun test tools` plus the render drift check is the verification, and Task 5 runs both against the integrated tree.

**Claim:** The archive has one shape, one bounty vocabulary, and one validator that refuses a file with an invented name, a stray slug, or a number the notes cannot back. (derived)
Machine: M1. `BOUNTY_NAMES` maps exactly five kinds to five display names: `hope-slayer` to "Hope Slayer", `cain` to "Cain and Abel", `seven-deuce` to "2-7 Showdown", `bubble` to "The Bubble", `kevin-deuce` to "Kevin Deuce", and no other key.
M2. `validateArchive(archive, games)` returns without throwing on a two-season fixture whose games between them use every field: `entrants` present and absent, a podium of three, a chop of two entries at place 1, an empty podium, a slugged entry, a handle-only entry, and bounties of every kind.
M3. `validateArchive` throws an Error naming the offending game's date (or, for a season-level fault, the season's `id`) for each of: (a) a `name` that fails `/^[A-Z][a-z]+( [A-Z]\.)?$/` and does not equal the entry's own `handle`; (b) a `slug` that names no player with a result in `games`; (c) `entrants` smaller than the number of distinct podium names; (d) a date that appears in two games; (e) a game dated on or after the earliest game in `games`; (f) a bounty `kind` outside the five; (g) podium places not non-decreasing, or a place outside 1 to 3; (h) an em dash (U+2014) in any `name`, `note`, or season `title`; (i) the word "experiment" in a `note`; (j) an empty `seasons` list, a season with an empty `games` list, or two seasons sharing an `id`.
M4. `validateArchive` accepts `name: "Gene"` with no initial, and accepts `name: "K5M Guy"` when `handle` is `"K5M Guy"`, and rejects `name: "K5M Guy"` when `handle` is absent.

    export type BountyKind = "hope-slayer" | "cain" | "seven-deuce" | "bubble" | "kevin-deuce";
    export type ArchiveEntry = { name: string; handle?: string; slug?: string };
    export type ArchivePodiumEntry = ArchiveEntry & { place: 1 | 2 | 3 };
    export type ArchiveBounty = ArchiveEntry & { kind: BountyKind };
    export type ArchiveGame = {

      entrants?: number;       // integer of at least one; absent when the notes do not say
      podium: ArchivePodiumEntry[];  // up to three; may be empty; places non-decreasing
      bounties: ArchiveBounty[];     // may be empty
      note?: string;           // one line
    };
    export type ArchiveSeason = { id: string; title: string; note?: string; games: ArchiveGame[] };
    export type ArchiveData = { seasons: ArchiveSeason[] };

`BOUNTY_NAMES` is a `Record<BountyKind, string>` with the five display names in M1; they match the trophy registry's names on purpose, but this module must not import `tools/lib/trophies.ts`: the registry lists what can be earned, and nothing here is earned. `validateArchive` checks the rules in M3 in the order listed and throws on the first failure, naming the game by `date` or the season by `id` in the message, in the refuse-and-name voice of `validateCoinHistory`. The name rule is: the name matches the expression, or the entry has a `handle` equal to its `name`. "Distinct podium names" for rule (c) counts distinct `name` strings on the podium. The earliest spine game for rule (e) is `min(games.games[].date)`. Test fixtures use invented names that satisfy the rule ("Ada W.", "Bly R.") and invented slugs; the `games` argument in tests is a minimal `GamesData` literal whose one game carries results for the slugs the fixture links.
